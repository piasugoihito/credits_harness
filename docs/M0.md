# M0 実現性スパイク 手順(Android 実機)

M0 画面のログには **件数・ホスト名・画面要素の有無だけ** が出ます(科目名・氏名・学籍番号は出ません)。
各手順のあと「ログ → コピー」で結果を共有してください。

## 準備
1. 端末で「開発者向けオプション → USB デバッグ」を有効にし、Mac に USB 接続。
2. `flutter run` (または `build/app/outputs/flutter-apk/app-debug.apk` をインストール)。

## 手順と確認したいこと

| # | 操作 | 見たいログ | 設計への影響 |
|---|---|---|---|
| a-1 | 資格情報を保存 → 「TWINS 時間割を取得」 | `自動入力: ok=true … ボタン=…` と `TWINS: 自動ログイン成功` | ボタン特定(R5)。失敗なら手動ログイン経路が主になる |
| a-2 | アプリを**完全終了**(履歴からスワイプ)→ 再起動 → もう一度取得 | `TWINS: ログイン済み(Cookie再利用)` | 出なければ毎回自動ログインが主経路(R4) |
| b | a の結果 | `TWINS: 春A 15コマ` など全タブ分 | タブ巡回が WebView で動くか |
| c | 「manaba 未提出課題を取得」 | `manaba: 未提出 N件`(実サイトと一致するか目視) | |
| d | TWINS 取得の直後に c | `manaba: ログイン済み(Cookie/SSO再利用)` なら SSO 共有あり | 共有なしなら各サイトで個別ログイン |
| d' | どこかで `許可ドメイン外への遷移を止めました: <host>` が出たら | そのホスト名 | IdP が tsukuba.ac.jp 外なら許可リストの見直しが必要 |
| e-1 | 「通知の権限を許可」→「2分後にテスト通知」→ アプリを完全終了 | 2分後に通知が届くか | |
| e-2 | 「6分後にテスト通知」→ 端末を再起動 | 再起動後に通知が届くか | 届かなければ起動時再スケジュールに頼る |
| f | 科目番号を入力 →「KdB を開く」→ 右上メニュー ①→②→③→④ | 検索欄の有無・結果件数・開いた後の URL・構造の要約 | シラバス本文の抽出方法を決める |

うまくいかない場合: 「Cookieをすべて削除」で初期状態に戻せます。自動ログインが1回失敗すると
**自動入力は止まり**ます(アカウントロック防止)。「再試行」を押すと1回だけ再開します。
