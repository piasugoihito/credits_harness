## 0. 新セッションへの引き継ぎ

**何を作るか**: TWINS(履修)・manaba(課題)・KdB(シラバス)の情報を端末内で集め、
「授業開始◯分前のローカル通知」「学期別の時間割表」「未提出課題の一覧」「科目ごとのシラバス表示」を提供するFlutterアプリ。

**現在地**: デスクトップ(Python + Playwright)のPoCで、ログイン・時間割取得・課題取得・シラバス検索フローの一部が動いた。
モバイル(Flutter)は**未着手**。要件はこの文書で確定させ、実装は次セッションから。

**読む順番**: この文書 → `reference/README.md`(信頼度表つき) → `reference/dart_sketch.md` → `reference/webview_snippets.js`。

**最初にやること**
1. §13「決定が必要な事項」D1〜D9をユーザーに確認する(推奨案つき)。
2. §14 の **M0(実現性スパイク)** を先に実施する。ここが通らないと設計が変わる(WebViewでのログイン維持、実機での通知)。
3. パーサーは `reference/fixtures` → `reference/expected` の**ゴールデンテストを先に書く**。

**守るべき前提(破らないこと)**
- 認証情報は端末のセキュアストレージのみ。サーバー・分析SDK・外部送信なし。
- 大学サイトに対して**読み取り専用**。履修登録/取消・課題提出など副作用のある操作を自動で行わない。
- 学年暦の日付を**推測で埋めない**(公式から転記)。
- 実データ(実際の科目・学籍番号・氏名を含むHTML/JSON)をリポジトリに入れない。

## 1. 目的と価値

| 課題 | 提供する価値 |
|---|---|
| 授業が始まる時間に気づけない | 授業開始N分前に、**何の授業か**をローカル通知する |
| 時間割の確認がTWINSで面倒 | 学期(モジュール)別の時間割表をアプリで一覧できる |
| 未提出課題を把握しづらい | manabaの未提出課題を一覧できる(**通知はしない**) |
| シラバスを探すのが手間 | 科目ボタンからシラバスを表示する |

**設計原則**: 少ない機能を確実に動かす / 端末内で完結 / 大学サイトへの負荷は最小 / 壊れたら黙らずに知らせる。

## 2. スコープ

### 2.1 MVPに含む
- 初回セットアップ(ログイン)
- 3タブ: **日程 / 課題 / 設定** + シラバス画面
- 授業開始◯分前のローカル通知(◯は設定で変更)
- 時間割・課題の取得(手動更新 + 起動時の自動更新)
- 学年暦(モジュール日程・休講・振替)の同梱データ
- GitHubリリース(Android APK、iOSビルド)

### 2.2 MVPに含まない
- 課題の通知・ウィジェット・カレンダー連携・課題提出
- 集中講義/その他の科目(時間割グリッドに出ない科目)
- 東京キャンパスの時限(1〜6限以外)・大学院独自の時間割
- 休講/教室変更の取り込み、成績・出席
- サーバー・アカウント・クラウド同期・分析/クラッシュ収集
- App Store / Google Play 公開(§13 D2で再検討)
- 英語UI

## 3. 用語

| 用語 | 意味 |
|---|---|
| モジュール | 学期の区切り。春A/春B/春C/夏休/秋A/秋B/秋C/春休(TWINSのタブ名) |
| コマ(スロット) | 曜日×時限×科目の1マス。曜日は1=月〜7=日、時限は1〜6 |
| ブロック | 同じ科目の連続した時限を1つにまとめたもの(1・2限 → 1ブロック、開始は1限) |
| 振替日 | 学年暦で「◯日は月曜日の授業を実施」と指定される日 |
| flowExecutionKey | TWINSの画面遷移ごとに変わる使い捨てトークン。URLの保存・再利用不可 |

## 4. 画面要件

ナビゲーション: **下部タブ3つ**(日程 / 課題 / 設定)。シラバスはタブ上にpushする詳細画面。

### 4.1 初回セットアップ
1. 免責表示(非公式・大学と無関係・自己責任・データは端末内のみ)への同意。
2. 学籍番号・パスワード入力 → セキュアストレージに保存。
3. 「ログインテスト」: WebViewでログインできるか確認。MFA等で自動ログインできない場合は**可視WebView**で手動ログイン(Cookieを保持)。
4. 通知権限の案内(後回し可)。
5. 初回の時間割・課題取得を実行して日程画面へ。

### 4.2 日程画面(学期別・履修中の科目表)
- 上部: モジュール選択(既定=学年暦から判定した「今日のモジュール」。手動で他モジュールも閲覧可)。
- 本体: **曜日×時限のグリッド**(月〜金を基本。土・日は登録があれば表示)。各セルに科目名(小さく科目番号)。空きコマは空欄。
- 科目セルをタップ → **シラバス画面**。
- 下に最終更新時刻。プルダウンで手動更新。取得失敗時はバナー(§FR-12)。
- (SHOULD)画面上部に「今日の授業」と開始時刻の簡易リスト。

### 4.3 課題画面(未提出のみ・通知なし)
- 締切が近い順。グループ: **期限切れ / 24時間以内 / それ以降 / 期限なし**。
- 各行: タイプ(レポート/アンケート/ドリル等)、タイトル、コース名、受付終了日時(相対表示も)。
- タップ → manabaの該当ページを**アプリ内WebView**で開く(ログイン済みセッションを共有)。
- プルダウンで更新。最終更新時刻を表示。
- 期限切れでも未提出なら一覧に残る(manabaの仕様。折りたたみ可)。

### 4.4 シラバス画面
- ヘッダー: 科目名・科目番号・(取得できれば)教員。
- 本文: 取得したテキスト。項目(授業概要/授業計画/成績評価方法 等)が分割できれば折りたたみセクション、できなければ全文。
- 「KdBで開く」ボタン(外部/アプリ内ブラウザ)を常設(取得失敗時のフォールバック)。
- 取得はユーザーがこの画面を開いた時に1回だけ。結果はキャッシュ(手動で再取得可)。

### 4.5 設定画面
| セクション | 項目 |
|---|---|
| アカウント | 学籍番号・パスワードの表示(マスク)/編集/削除、ログインテスト、ログアウト |
| 通知 | 授業通知 ON/OFF、**何分前**(5/10/15/20/30/60、既定10)、権限状態と設定アプリへの導線、テスト通知 |
| データ更新 | 起動時に自動更新 ON/OFF、更新間隔(時間)、今すぐ更新 |
| 学期 | 「今日のモジュール」を自動判定/手動固定 |
| データ | キャッシュ削除、全データ削除 |
| 情報 | バージョン、ライセンス、免責、プライバシー、GitHub |

## 5. 機能要件

優先度: **MUST**=MVP必須 / SHOULD=できれば / COULD=将来

| ID | 優先 | 要件 | 受け入れ基準(要約) |
|---|---|---|---|
| FR-1 | MUST | **認証情報管理**: 学籍番号・パスワードをKeychain/Keystoreに保存。平文ファイル・ログ・クラッシュに出さない | 保存後にアプリを再起動しても使える。設定で削除すると消える。ログにパスワードが出ない |
| FR-2 | MUST | **ログイン/セッション**: 未ログイン検出→保存済み資格情報で自動入力を**1回だけ**試行→失敗なら失敗フラグを立てて可視WebViewで手動ログイン。自動再試行しない(ロック防止) | 失敗後は再度自動入力しない。ユーザーが資格情報を更新するか「再試行」を押すと1回だけ試す |
| FR-3 | MUST | **時間割取得**: TWINSの「履修登録・登録状況照会」を開き、全学期タブを巡回してコマを取得→DB置換 | 実機で全タブ取得。0件/パース失敗時は既存データを上書きしない |
| FR-4 | MUST | **課題取得**: manabaの「未提出の課題一覧」を取得→DB置換 | 一覧が実サイトと一致。ボタン/表が見つからなければ上書きせず警告 |
| FR-5 | MUST | **日程画面**(§4.2) | モジュール切替でグリッドが変わる。セルタップでシラバスへ |
| FR-6 | MUST | **課題画面**(§4.3) | 締切順・グループ表示。タップでmanaba表示 |
| FR-7 | MUST | **シラバス**(§4.4): KdBを科目番号で検索→最初の(科目名一致優先の)結果を開き本文を取得・キャッシュ | 初回のみ通信し、2回目以降はキャッシュ。失敗時は「KdBで開く」が使える |
| FR-8 | MUST | **授業開始通知**(§8) | 設定した分数前に、科目名と開始時刻を通知。アプリ終了状態でも届く |
| FR-9 | MUST | **設定画面**(§4.5) | 各項目が永続化され、通知は設定変更後に再スケジュールされる |
| FR-10 | MUST | **学年暦**(§9): モジュール日程・休講日・振替日を同梱JSONから読む | 今日のモジュールが正しく判定される。振替日に指定曜日の授業が通知される |
| FR-11 | MUST | **更新ポリシー/オフライン**: 起動時に、最終成功から設定間隔を超えていれば更新。手動更新はいつでも。オフラインならキャッシュ表示 | 機内モードでも直近のデータが見える |
| FR-12 | MUST | **エラー表示**: 「再ログインが必要」「取得失敗(構造変更の可能性)」「オフライン」を区別して、画面上のバナーで知らせる。黙って古いデータを最新扱いしない | 各状態で最終成功時刻とバナーが出る |
| FR-13 | SHOULD | 「今日の授業」ビュー(日程画面の上部) | 今日の授業が時刻順に並ぶ |
| FR-14 | SHOULD | 通知タップ→該当科目のシラバス画面へ(payload=科目番号) | タップで開く |
| FR-15 | SHOULD | バックグラウンドでの通知再スケジュール(定期タスク)。アプリを1〜2週間開かなくても通知が切れにくくする | Android/iOSで実機確認(iOSはベストエフォート) |
| FR-16 | COULD | 科目ごとの通知ミュート | |
| FR-17 | COULD | 集中講義/その他の科目 | |
| FR-18 | COULD | 課題タブのバッジ(24時間以内の件数)。**通知はしない**方針は維持 | |

## 6. アーキテクチャ方針

**端末内完結**(サーバーなし)。モバイルにはPlaywrightが無いため、**WebViewをブラウザ代わり**にする。

```
[UI: Riverpod] ─ [Repository] ─┬─ Scraper(WebView + JS注入 → HTML文字列)
                               ├─ Parser(package:html, 純Dart・ゴールデンテスト)
                               ├─ DB(SQLite: drift/sqflite)
                               ├─ SecureStorage(資格情報)
                               └─ NotificationScheduler(flutter_local_notifications + timezone)
```

| 領域 | 推奨 | 理由/注意 |
|---|---|---|
| WebView | `flutter_inappwebview`(`HeadlessInAppWebView` + 可視`InAppWebView`) | 画面なし取得+手動ログインの両立。JS注入・Cookie管理が可能 |
| 取得の流れ | JSで操作(`reference/webview_snippets.js`)→ `outerHTML` をDartへ→パース | TWINSは`flowExecutionKey`で状態遷移するため、HTTP直叩きでなくメニュー/タブを**順にクリック**する必要がある |
| パース | `package:html` | PoCのBeautifulSoupロジックを移植。**表が無い/0件はnullを返し、呼び出し側が上書きを拒否** |
| 通知 | `flutter_local_notifications` + `timezone`(Asia/Tokyo) | 端末ローカルで完結。プッシュ用サーバー不要 |
| 保存 | SQLite(時間割・課題・シラバス・同期状態) + `shared_preferences`(設定) | |
| 秘密 | `flutter_secure_storage` | iOS Keychain / Android Keystore |
| 状態管理 | Riverpod(推奨) | 好みで可 |

**セキュリティ上の構造要件**
- WebViewの**ナビゲーションを `*.tsukuba.ac.jp` に限定**(`shouldOverrideUrlLoading`)。自動入力・JS注入も許可ドメインでのみ実行(フィッシング/リダイレクト対策。サフィックス偽装 `twins.tsukuba.ac.jp.evil.com` も弾く)。
- 自動化が押せる要素を**許可リスト方式**にする(学期タブ・メニュー・『未提出の課題一覧』ボタン・KdBの検索/結果のみ)。`DeleteCallA`/`InputCall*` 等は実行禁止(JS側 `assertSafe` + Dart側でも二重に)。
- IdP(統一認証)のホスト名は未確認。M0で確認して許可リストに追加。

**プラットフォーム固有(通知)**
- Android: `POST_NOTIFICATIONS`(13+の実行時権限)、正確なアラーム(`SCHEDULE_EXACT_ALARM`。拒否時は不正確スケジュールにフォールバックし設定画面で警告)、再起動後の復元(`RECEIVE_BOOT_COMPLETED`)、電池最適化の案内。通知チャンネル「授業開始」(高重要度)。
- iOS: 通知権限。**保留中のローカル通知は64件まで** → §8のウィンドウ方式。

## 7. データモデル(論理)

| テーブル | 主なカラム | 備考 |
|---|---|---|
| `slots` | module, day(1-7), period(1-6), code, name, teacher, year | PK=(module, day, period, code)。取得成功時のみ全置換 |
| `assignments` | id(PK, 例 `course_…_survey_…`), type, title, url, course, course_url, start, due(null=期限なし), last_seen | 取得成功時に置換(一覧から消えた=提出済み等) |
| `syllabus` | code(PK), name, url, fetched_at, text, sections_json | 手動再取得可 |
| `sync_state` | source(twins/manaba/kdb), last_success_at, last_error, last_error_kind | FR-11/12 |
| 設定(KV) | notify_enabled, notify_lead_minutes, auto_refresh, refresh_hours, module_override, autofill_failed | 失敗フラグ=FR-2 |

正規化の注意: 同じ科目が複数モジュールに現れる(例: 秋Aと秋B両方)ので、`slots` はモジュール別に持つ(各タブの結果をそのまま保存)。**タブは学期ごとに正確なコマを返す**(秋Aにだけある科目がある)ので、日付→モジュール判定して該当タブのコマを使う。

## 8. 通知仕様(授業開始N分前)

**入力**: 設定(N分)、`slots`、学年暦(§9)、時限の開始時刻(`reference/period_times.json`)。

| 時限 | 開始 | 終了 |
|---|---|---|
| 1 | 08:40 | 09:55 |
| 2 | 10:10 | 11:25 |
| 3 | 12:15 | 13:30 |
| 4 | 13:45 | 15:00 |
| 5 | 15:15 | 16:30 |
| 6 | 16:45 | 18:00 |

**生成規則**
1. 今日から `windowDays`(既定14日)先まで、日ごとに: 休講日ならスキップ → 有効モジュールを判定 → **有効曜日**(振替日はoverride)のコマを取得。
2. 同じ科目の**連続時限は1ブロック**に結合(1・2限 → 通知は1件、開始は1限)。同じ科目でも連続しないコマ(2限と5限)は別ブロック。
3. `fireAt = ブロック開始 − N分`。過去のものは捨てる。
4. 近い順に**最大60件**(iOSの64件制限に余裕)。
5. **常に全キャンセル→全登録**(差分更新しない=冪等)。通知IDは 日付+科目+時限 から決定的に作る。

**文面**: タイトル=科目名 / 本文=`10分後 08:40 開始（1・2限）`。payload=科目番号。

**再スケジュールのトリガー**: 起動時 / 時間割更新成功 / 設定変更 / 学年暦更新 /(SHOULD)バックグラウンド定期実行。
**OFFにしたら**保留中の授業通知をすべて取り消す。課題・シラバスに関する通知は**一切出さない**。

**受け入れ基準(例)**
- 月曜1・2限の科目、N=10 → 月曜08:30に1件だけ通知(2限分は出ない)。
- 火曜が振替で「月曜の授業を実施」の日 → その日は月曜の科目が通知される。
- 祝日/休講日 → その日の通知なし。
- アプリを終了した状態でも通知が届く(実機)。

## 9. 学年暦データ

**必要な理由**: TWINSのコマ情報に日付がない。「今日は秋Aか秋Bか」「振替日」「休講日」を知るために必須。

**形式**: `reference/academic_calendar.example.json`(スキーマ)。年度ごとに1ファイル、アプリに同梱。
(SHOULD)リポジトリのrawファイルを取得して更新できるようにし、アプリ更新なしで年度データを差し替えられる。取得失敗時は同梱版にフォールバック。

**確認済みの事実(公式ページより。要原典再確認)**: 2026年度 筑波キャンパス — 春学期授業 2026-04-14〜08-06、秋学期授業 2026-10-01〜2027-02-15。
**未記入(公式学年暦から転記が必要)**: 各モジュールの開始/終了日、休講日(祝日・学園祭・スポーツデー・期末試験日等)、振替日。
参考: 過去年度の学年暦には「◯日は月曜日の授業を実施」の振替記載がある(2025年度)。モジュール日程は年度で変わる(2025年度履修要覧は秋A=10/1〜11/7、秋B=11/11〜12/19、秋C=1/5〜2/12)ので**2026年度に流用しない**。

出典: https://www.tsukuba.ac.jp/campuslife/calendar-school/

## 10. 非機能要件

### 10.1 セキュリティ・プライバシー
| 要件 | 内容 |
|---|---|
| 資格情報 | Keychain/Keystoreのみ。ログ・例外・クラッシュ・スクリーンショット共有に出さない |
| 通信先 | `*.tsukuba.ac.jp` のみ(+任意で学年暦のGitHub raw)。分析・広告・クラッシュ収集SDKを入れない |
| 端末バックアップ | Androidは資格情報・DBをバックアップ対象外(`allowBackup=false`等)。iOSはKeychainを`this_device`系にする |
| ログイン失敗 | 自動再試行しない(FR-2)。パスワード誤りの連続試行によるロックを防ぐ |
| データ削除 | 設定から全削除・ログアウトができる(Cookie含む) |
| 免責 | 非公式・自己責任・大学の利用規程は各自が確認。アプリ内とREADMEに明記 |

### 10.2 サイトへの配慮
- TWINS/manaba: 起動時・手動更新のみ。定期的な高頻度ポーリングはしない(既定は最終成功から6時間以内なら再取得しない)。1回の更新でアクセスするページ数を最小に。
- KdB: **robots.txtで自動アクセス不可**。ユーザーが科目ボタンを押した時に**1科目1回**のみ、結果をキャッシュ、一括プリフェッチ禁止。「KdBで開く」導線を併設(§13 D3)。

### 10.3 信頼性・保守
- パース失敗(表なし・0件・急減)は**上書きせず**警告。構造変更に気づけるようにする(FR-12)。
- セレクタ・正規表現はパーサー内に集約し、フィクスチャのゴールデンテストで守る。
- 大学サイトの改修が主要リスク。壊れた時は、個人情報を含まない診断情報を添えてGitHub Issueを作る導線(COULD)。

### 10.4 性能・互換
- 更新はバックグラウンドで実行し、UIをブロックしない。取得中はインジケータ。
- 推奨最低OS: Android 8.0(API 26)以上 / iOS 14以上(採用パッケージの要件で最終確認 §13 D8)。
- UI言語: 日本語のみ(MVP)。ダーク/ライトはシステム追従。

## 11. 配布・CI/CD

**方針**: GitHubリポジトリ + Releases でビルド成果物を配布(ストア公開はしない)。

| 成果物 | 内容 | 注意 |
|---|---|---|
| Android | 署名済みAPK(`app-release.apk`)+ SHA-256 | 署名キーストアはGitHub Secretsで管理。「提供元不明のアプリ」の手順をREADMEに |
| iOS | **未署名IPA**(`flutter build ios --release --no-codesign` → `Payload/`をzip)と、ソースからXcodeでビルドする手順 | 個人配布は**サイドロード**(AltStore/SideStore/Sideloadly等)。無料Apple IDでは署名が**約7日で失効**し再署名が必要。広く配るなら§13 D2 |

- CI(GitHub Actions): PR時に `flutter analyze` / `flutter test`(ゴールデンテスト含む)。タグ `vX.Y.Z` でAndroid(ubuntu)/iOS(macos)をビルドしReleaseに添付。
- バージョニング: SemVer、`CHANGELOG.md`(Keep a Changelog)。
- リポジトリ必須ファイル: `README.md`(免責・導入手順・スクリーンショット)、`LICENSE`、`PRIVACY.md`(端末内のみ・収集なし)、`SECURITY.md`(脆弱性の連絡先・資格情報の扱い)、`.gitignore`(実データ・キーストア・`.env`)。
- (COULD)シークレットスキャン(gitleaks)をCIに入れ、実データ/学籍番号の混入を防ぐ。

## 12. テスト方針

| 層 | 内容 |
|---|---|
| パーサー(最重要) | `reference/fixtures` → `expected` のゴールデンテスト。Pythonの出力とDartの出力が一致すること |
| 学年暦/モジュール判定 | 境界日(モジュール初日・最終日)、振替日、休講日、モジュール外(夏休/春休) |
| 通知プラン | ブロック結合、非連続の別ブロック、過去の除外、60件上限、振替日、OFF時に全取消 |
| WebView JS | `webview_snippets.js` はjsdomテストあり(許可ドメイン・禁止操作・自動入力)。実機での動作はM0で検証 |
| ウィジェット | 日程/課題/設定の主要状態(データなし・エラーバナー・オフライン) |
| 実機E2E(手動) | ログイン→更新→通知が実際に届く(アプリ終了状態・再起動後)、機内モード、セッション切れ |

フィクスチャは**架空データのみ**。実HTMLを取り込む場合は必ず個人情報を除去。

## 15. MVP受け入れ基準(全て満たすこと)
1. 初回セットアップでログインでき、時間割と課題が取得できる。
2. 日程画面でモジュールを切り替えると、実TWINSの各学期と一致する時間割が出る。
3. 科目をタップするとシラバス画面が開き、テキストまたは「KdBで開く」が使える。
4. 授業開始N分前に、科目名と時刻つきの通知が届く(アプリ終了状態・端末再起動後を含む)。連続時限は1通知。
5. Nを設定で変えると通知が作り直される。OFFで全て取り消される。
6. 課題画面に未提出課題が締切順で並び、通知は一切出ない。
7. 取得に失敗しても既存データが消えない。画面に理由が出る。
8. 資格情報がログ・バックアップ・平文ファイルに残らない(確認手順あり)。
9. リポジトリに実データ・秘密が含まれない(gitleaks等で確認)。
10. GitHub ReleaseからAndroid APKを入れて動く。iOSはドキュメント通りにビルド/サイドロードできる。
